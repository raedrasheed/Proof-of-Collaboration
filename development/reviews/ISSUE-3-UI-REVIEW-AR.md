# مراجعة أداة المتابعة — Issue #3

هذه أداة محلية، وليست تنفيذًا لشبكة PoCol. تعتمد على PR #2 والمسودة المتحققة 0.8. حفظ المنسق نقطة استئناف قبل العمل؛ بقيت بصمات 139 ملفًا من الأساس والمواصفات والمتجهات مطابقة. قرارات المالك ما زالت مفتوحة.

Claude كتب الأداة وتعديلاتها. Codex راجع الملفات واختبرها بصورة مستقلة. أعيد استعمال تنسيق PoCol Dialogue وفحوص الاتصال المحلي؛ لم تُشغّل حلقته القديمة.

## الدورة الأولى والثانية

| الدليل | النتيجة |
|---|---|
| مراجعة النسخة الأولى | 20 اختبارًا ناجحًا، وإخفاقان من 22؛ أمر الاختبار المختصر لم يعمل على Node 22 |
| تعديلات Claude التالية | إصلاح عرض الردود والمراجعات الجديدة، تقييد أدوات القراءة والكتابة، تنظيف عقد العامل عند الإخفاق، منع الدورة التالية قبل المراجعة |
| فحص Codex للنسخة المعدلة | `npm test --prefix tools/local-coordinator`، Node v22.13.1، خروج 0: 35 ناجحًا، صفر إخفاق/تجاوز |
| اتصال خادم Codex الموجود | نجح initialize وقراءة معرّف الجلسة الحالية عبر WebSocket؛ نجح أمر queue إلى الجلسة نفسها بخروج 0 |

إشعار queue ليس مراجعة ولا موافقة. لا تنشئ الأداة جلسة أخرى أو مراجعًا آخر. رموز الخدمة وإيصالات الوكلاء الكاملة محفوظة محليًا خارج Git.

## الدورة الثالثة: الربط الفعلي

أضاف Claude إشعارات أحادية عبر `codex queue --remote unix://` إلى جلسة المنسق الحالية. فحص Codex المستقل: **47 اختبارًا ناجحًا، صفر إخفاق، خروج 0**. لا يمر نص المتصفح أو الرموز إلى سطر أمر الإشعار، ولا تُشغّل جلسة أخرى.

نجحت دورة Chrome الحقيقية: إرسال مزدوج بتوجيه واحد، استلام Codex عبر API الخاص، جواب UI-TEST دون أي قرار M1، استدعاء Claude الفعلي في جلسته المحفوظة، إيقاف آمن ينتظر انتهاءه، مقارنة رده بنتائج 0.8، تسجيل المراجعة الفعلية وظهورها تلقائيًا، وأربع إيصالات queue ناجحة إلى الجلسة نفسها. نجحت إعادة فتح الصفحة دون استدعاء جديد؛ بقيت بصمات 139 ملفًا مطابقة.

نجح أيضًا اختبار إخفاق حقيقي في مساحة اختبار معزولة: رفض Claude معرّف جلسة غير موجود بخروج 1، ظهر الإخفاق وحُفظ، استوردته الخدمة بعد إعادة التشغيل دون تكراره، ثم نجحت إعادة صريحة من المتصفح باستخدام جلسة Claude الأصلية ومراجعة Codex الفعلية. هذه تجربة اتصال؛ لا تُثبت اكتمال M1.

## نتائج الفحص الإضافي

وجد فحصان مستقلان خارج اختبارات الوحدات خللين: ملف قفل خدمة فارغ يُعامل خطأً كقفل قديم، ومعرّفات محاولات الإشعار تتكرر بعد تقليص تاريخها إلى 20 محاولة، فتعلق المحاولة اليدوية التالية في «جارٍ الإرسال». الإصلاح مطلوب؛ لذلك تبقى Issue #3 مفتوحة والطلب Draft. لا دمج أو نشر عام. لا نكتفي باجتياز اختبارات الوحدات.

## الدورة الرابعة

أصلح Claude ملكية قفل الخدمة والاستعادة الحصرية، وحفظ دليل القفل القديم. أضاف عدّاد محاولات دائمًا ومفاتيح إعادة محفوظة لا تضيع عند اختصار العرض. فحص Codex المستقل نجح: **54 اختبارًا، صفر إخفاق/تجاوز، خروج 0**؛ ونجح الفحصان اللذان كشفا UI07 وUI08 سابقًا. فُحصت 27 إعادة يدوية فاشلة في اختبار محقون، مع إعادة المفتاح القديم بعد إعادة التحميل؛ هذا اختبار للمنطق، وليس 27 استدعاءً فعليًا للوكيل.

بقي ضبط التشغيل بأمر واحد من الإعداد الخاص المحفوظ، وتنقيح معرفات الاختبار وأمثلة التشغيل، ثم إعادة اختبار المتصفح على الملفات النهائية. تقارير الدورات السابقة محفوظة؛ الطلب يبقى Draft.

## التحقق النهائي — الدورة الخامسة

نجحت **59 من 59** على Node v22.13.1، دون إخفاق أو تجاوز، بخروج 0. نجحت الفحوص الإضافية السابقة. شُغّلت الخدمة النهائية بأمر التشغيل الواحد بعد إزالة متغير معرّف الجلسة من بيئة عملية التشغيل؛ استعادت إعداد الخيط الصحيح من ملف الاتصال الخاص، دون إعادة رموز الاتصال القديمة أو بدء خادم Codex جديد. صار طلب فحص Claude يتبع آخر مسودة في السجل بدل افتراض 0.8 دائمًا.

أعيدت التجربة كاملة على الملفات النهائية باستخدام Chrome 154.0.8037.95 وPlaywright 1.51.1، مع Claude Code 2.1.292 والخادم الحالي لـCodex 0.160.1. نجحت عشرة فحوص متصفح، وثلاثة فحوص إخفاق واستعادة فعلية. بقيت 139 بصمة أصلية وسجل M1 نفسه مطابقين لنقطة الاستئناف. لا توجد موافقة على أسئلة المالك الحقيقية.
