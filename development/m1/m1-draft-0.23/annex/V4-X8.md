## 3. Fixture pages (P, traceable to H)

- `pages/C1…C8/{index.html, main.js}` are literal assets.
- **Substitutions.** `__CANARY_HOST__` (an IP literal, so no DNS lookup) and `__RUN__` are the only ones.
- **Script-only attempts.** Every counted attempt is made by script at run time. The static sanitizer therefore cannot defeat the K4 control; static-markup sanitization is covered by T12 and X1–X7.
- **Page log.** Each page records `window.__x8 = {channel, run, attempts[{id, api, target, error}], extensionApi}`. The `extensionApi` field is an informational `typeof` probe; X4 is the gate for extension APIs.
- **Paths.** HTTP paths carry `/x8/<run>/<channel>/<attempt>`.

## 5. Event-log schema

- **canaryEvent:** `{runId, K, C|'selftest', ts, proto, port, srcIp, srcPort, bytes, firstBytesHex(≤64 B), http{method, path}|null, evidenceSource:'canary'}`. `srcIp` must be the Chrome host.
- **secondaryEvent** (H): `{runId, K, C, ts, kind tcpConnection|udpEndpoint, pid, local, remote, evidenceSource}`.
- **dnsEvent** (P): `{runId, K, C, ts, qname, evidenceSource}`.
- **pageLog** (P): `window.__x8`, read through CDP.

## 6. Experiment plan (specified, not executed)

**Environment:**
- a separate Chrome user-data-dir and an unpacked test build per K (flags `x8Csp`, `x8Dnr`, `x8Rtc`);
- CDP bound to 127.0.0.1;
- CanarySink on the host LAN IP or a second machine;
- the secondary monitor and a DNS log;
- the eight pages published as one site through the factory on anvil-br.

**Schedule** (P): for each K in K0..K5, first SELFTEST, then C1..C8, one page per 15000 ms window with a 3000 ms gap.

| ID | Inputs | Pass criterion |
|---|---|---|
| X8-SELFTEST-<K> | one TCP connection per TCP port and one UDP datagram per UDP port, from a non-Chrome process | All five are logged. Otherwise the K block is **INVALID**: a zero would be a false zero. |
| X8-<K>-<C> (48) | page C<n> under build K | The cell rule: gatingZero (K0–K2 all; K5 C5–C7), requiredReach on the channel's expected port (K4), informational (K3; K5 C1–C4 and C8). |
| X8-SEC-K0 | secondary monitor and DNS log during K0 | zero signals |
| X8-F1 | a K0 build whose test hook rejects `updateSessionRules` | no frame, no `window.__x8`, zero reach |
| X8-FULL (H) | packet capture on a separate machine | before a public release; not part of M1 |

**Verdict:**
- **INVALID** if any self-test misses a port.
- Otherwise **FAIL** on any gatingZero reach (a K0 reach is a release blocker, and governance withdraws the extension) or any K0 secondary or DNS signal.
- Otherwise **PENDING** if a K4 channel does not reach its expected port, or a window is missing.
- Otherwise **PASS**. Informational cells are reported as reach, noReach or unexplained.

`tools/x8_eval.py` implements this rule offline, and 14 synthetic logs with hand-derived verdicts exercise it. They are not Chrome results.

## 7. Claim limits (H, consistent with B)

- X8 shows blocking of the **counted** channels only. An uncounted channel toward another destination is not covered.
- Destination independence is an argument (no layer distinguishes destinations except the chrome-extension exception), not a proof.
- RtcLockdown's argument stays unproven. A passing X8 does not prove that WebRTC exposure is impossible.
