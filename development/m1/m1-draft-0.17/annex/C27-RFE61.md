**Timer order used.**
- Same as 0.13/0.16: at equal time and priority, the earlier-scheduled timer runs first.
- `_start_attempt` schedules the attempt's wait timer before the grant schedules the tomb deadline.

## 3. RF-E6-1: x12 and x12b, supplemental full timeline

**The omitted cell.** T2a is issued at t=1, so its 5000 ms deadline falls at **5001**. Attempt 2 for op2 (T2b) is then queued behind T1b, while T2a keeps slot B until 7000. The source does not write this cell. It is tagged `derived`; source cells are tagged `source`.

| Mode | 6000 | 7000 | stale op1 / op2 / total |
|---|---|---|---|
| x12 (source) | T1b withdrawn; A → T3a | T2b withdrawn; T1b and T2b discarded as withdrawn | 0 / 0 / **0** |
| x12b, global adminNoCancel (source fault) | nothing withdrawn; A → T3a | B returned by T2a → T1b fails the guard → B → T2b fails the guard (op2 resolved in this same step) | 1 / 1 / **2** |
| x12b-op1only (**analysis mode, not a source fault**) | op1's request kept | T2b withdrawn; T1b fails the guard; T2b discarded | 1 / 0 / **1** |

**All three modes have:**
- the same seven sets;
- next seq K1 3, K2 2, K3 2, so no allocation for any stale request;
- 7 DiskLedger tickets, 3 of them tombs, so no ticket for a stale request;
- no tomb issued after its operation's resolution;
- K1 recreated as `{k9:'n'}` in memory and at the next generation;
- held 1 at 7000 and 0 at 8000;
- one reply per message.

**Reconciliation.** This is a technical fixture proposal, not an owner-policy approval.
- **Blocker:** under the source's own fault definition (withdrawal disabled, no per-op scope), the total is 2. The literal `adminStaleDropped = 1` holds only as op1's count, or if withdrawal is disabled for op1 alone. Choosing between these changes the baseline's meaning.
- **Option A:** amend the x12b text by adding the 5001 cell, and state `adminStaleDropped = 2 (op1 1, op2 1)` with zero alloc, ticket and set for both.
- **Option B:** scope the fault to op1; the total is then 1, as shown by the analysis mode.
- **Option C:** keep the text and read "= 1" as op1's count.
- **Fixtures:** they assert all three modes. The literal is checked as op1's count (`RF-E6-1.x12b.literalWitnessOp1`). The total 2 stays a recorded partial gap (`RF-E6-1.x12b.literalTotal`) until owner or root chooses.
