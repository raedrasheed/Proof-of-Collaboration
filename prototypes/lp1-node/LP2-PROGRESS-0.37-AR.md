# تقدم LP2 — قبول رؤوس مرشحة بشكل دائم (مراجعة المؤلف 1، نقل 0.37)

**الحالة:** كُتبت الشيفرة والاختبارات ولم تُجمَّع ولم تُشغَّل لدى المؤلف. لا إعلان قبول قبل أن ينفّذ الجذر P0–P8 ويراجعها Codex.

**ما يعمل في التصميم:** سجل محلي تجريبي لرؤوس مرشحة.

- يُقبل الرأس بعد فك ترميز صارم وفحوص H-pre المحددة (NetID والبنود 2–9 والارتفاع والأب وH_END)، بسقف `U256::MAX` ودون ساعة حائط.
- تربط البيانات الوصفية بصمة SHA-256 لبايتات ملف الملف الشخصي بعينها، مع genesisHash وchainId.
- السجلات مرتبطة بالبصمات ولها مجاميع تحقق متسلسلة وحارس للطول وعلامة إيداع، وحدود صارمة تُفحص قبل أي تخصيص للذاكرة.
- الكاتب حصري على Windows عبر `share_mode(0)`، ويحرّره نظام التشغيل عند انهيار العملية، ولا توجد ملفات قفل.
- تُتحقق الدفعة كاملةً قبل أي كتابة، ثم يُكتب كل سجل ويُزامَن على حدة. الذرية لكل سجل لا لكل دفعة، وأي خطأ كتابة يُعطّل الكاتب حتى إعادة الفتح.
- الذيل الممزق يُبلَّغ عنه بوصفه «يحتاج استرداد». الاسترداد ينسخ البادئة المتحقق منها إلى مجلد جديد فقط، ولا يمسّ المصدر أبدًا.

**الحالة المعلنة دائمًا:** `candidate` و`awaiting: H-full` و`executedHeight = 0` و`consensus = false`. لا تنفيذ ولا سلسلة قانونية ولا إجماع حي.

**القيود:**

- الكاتب مدعوم على Windows فقط، ولا يُدّعى قفل محمول على غيره.
- لا مزامنة لمدخلات المجلد.
- السجل خطي ولا يقبل فروعًا. رفض الفرع ليس حكمًا ببطلان الكتلة.
- الصيغة تجريبية وقد تتغير دون ترحيل، وليست التصميم النهائي redb/RetentionStore.
- رؤوس التجهيزات المضافة في الاختبارات ليست إنتاجًا حيًا للكتل.

**ما بعده:** يأتي LP3 (genesis قابل للإقلاع وParamGate) ثم LP4 (تنفيذ EVM وH-full) بعد قبول LP2. يبقى التنفيذ والإجماع الحي والإنتاج والمزامنة للمراحل التالية. مواصفة M1 0.32 دون تغيير.
